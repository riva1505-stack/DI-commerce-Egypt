# DI Commerce Egypt — Restaurant Edition v1.0

**برنامج ويب تجريبي لمطعم واحد — واجهة عربية RTL كاملة بهوية جديدة (أسود × ذهبي × فوشيا)، وصوت وكتابة، ومنيو وسلة ولوحة إدارة.**

الملف يحتوي على **الكود التشغيلي** وليس صور تصاميم فقط. يصلح للتجربة محليًا، لكنه **غير منشور** ولا توجد خدمة AI أو صوت مدفوعة مفعلة دون إدخال مفتاح مناسب. بيانات المنيو والأسعار أمثلة فقط وليست خاصة بمطعم حقيقي.

## التشغيل الأسهل على Windows 10/11

1. فكّي الضغط عن ملف ZIP بالكامل على الكمبيوتر.
2. ثبّتي Python **3.11 أو أحدث**، مع تفعيل خيار `Add Python to PATH`.
3. افتحي الملف `run_windows.bat` داخل مجلد البرنامج. أول تشغيل يحتاج إنترنت لتثبيت المكتبات المذكورة في `requirements.txt`.
4. سيفتح المتصفح على `http://127.0.0.1:8000` (ويمكن كتابته يدويًا إذا لم يُفتح تلقائيًا).
5. للإدارة افتحي `http://127.0.0.1:8000/admin/login` ثم أدخلي كلمة مرور **التجربة المحلية فقط**: `demo12345`.
6. أنشئي طلبًا من واجهة الزبون، ثم ادخلي لوحة الإدارة لتغيير حالة الطلب.

**Mac / Linux:** شغلي `sh run_mac_linux.sh` من مجلد المشروع، أو اتبعي الخطوات اليدوية أدناه.

### التشغيل اليدوي

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
python start.py
```

## ماذا يحتوي البرنامج؟

- **واجهة الزبون**: شعار البرنامج الفعلي، صفحة مطعم، قائمة أصناف مع فلاتر وبحث وأسعار وصور توضيحية بالرموز؛ تفتح على الهاتف والكمبيوتر.
- **مساعد المطعم**: محادثة نصية ترشد الزبون للوجبة من المنيو الفعلي، تسأل عن التفضيلات والميزانية وتقترح بدائل حقيقية. إذا أدخلتِ API مناسبًا على الخادم يمكن تفعيل ردود AI مولّدة.
- **الصوت مع النص**: زر ميكروفون لتسجيل رسالة صوتية أو إملائها وتحويلها إلى نص، وزر تشغيل الردود صوتيًا. عند توفر خدمة خادم للصوت يعمل بدون الاعتماد الحصري على SpeechRecognition في المتصفح. هناك مسار احتياطي لبعض المتصفحات؛ في غياب خدمة مناسبة تبقى الكتابة متاحة.
- **طلب وسلة**: اختيار أصناف وإضافات وكميات، حساب السعر، توثيق رقم الطاولة، تأكيد السعر من قاعدة البيانات، وإرسال الطلب للمطعم؛ مع منع بعض حالات التكرار.
- **لوحة الإدارة**: عرض الطلبات، تغيير الحالة، تعديل الأصناف وأسعارها وتوافرها، إضافة أصناف، تغيير اسم المطعم وعدد الطاولات، توليد QR للطاولات.
- **الهوية المرئية**: هوية نصية جديدة بعلامة DI في صفحات الزبون والإدارة؛ نظام ألوان موحّد في `static/brand.css` لواجهة الزبون، المساعد، السلة، شاشة الدخول ولوحة الإدارة. يُراعى حجم شاشة الموبايل.

## تشغيل الذكاء الاصطناعي والصوت

بشكل افتراضي **المساعد النصي الإرشادي يعمل دون اشتراك**؛ لا يُمثل النموذج التوليدي الكامل. لتفعيل **المحادثة الذكية والصوت على الخادم**:

1. انسخي `.env.example` إلى ملف `.env` في نفس المجلد.
2. ضعي مفتاح الـAPI في `OPENAI_API_KEY=`؛ **لا تضعيه في JavaScript أو في أي مكان يمكن للزبون رؤيته**. هذا الربط يتطلب حسابًا ورصيدًا لدى المزوّد.
3. أعيدي تشغيل `start.py` أو `run_windows.bat`.
4. جربي التسجيل والسماع على جهازك، ثم على Safari وChrome وFirefox وEdge قبل أي إطلاق. بعض المتصفحات تحتاج إذن الميكروفون وتفاعل المستخدم والاتصال عبر HTTPS عند النشر.

يمكن أن تختلف الأصوات العربية وجودتها حسب المزود. حدود التسجيل في الواجهة 12 ثانية لكل مقطع. إذا تعذّر الصوت تبقى الرسائل النصية متاحة. **لم تُنفّذ مكالمة AI مدفوعة أو اختبار حقيقي على Safari في هذا التسليم.**

## ما لم يتم تضمينه

الدفع الإلكتروني، الربط المباشر مع POS أو المخزون، واتساب، منصة متعددة المطاعم/حسابات منفصلة، الاشتراكات المالية وإصدار الفواتير الضريبية. هذه وظائف تطوير لاحقة. التسجيل الصوتي ليس تشغيلًا تلقائيًا مستمرًا في الخلفية، ويحتاج ضغطًا من الزبون وإذنًا للميكروفون.

## بيانات وملاحظات مهمة للإنتاج

- تحديث أمان تسجيل الدخول: راجعي [AUTH_SECURITY.md](AUTH_SECURITY.md) قبل النشر. يمكن توليد `ADMIN_PASSWORD_HASH` بالأمر `python hash_admin_password.py` بدل حفظ كلمة المرور نفسها. الجلسات قابلة للإلغاء عند الخروج، ومحاولات الدخول محدودة عبر SQLite. ملف `DI2.zip` هو الأرشيف الأصلي ولا يحتوي على هذه التحديثات.

- **لا تنشري هذا المشروع بإعدادات التجربة**. غيّري `ADMIN_PASSWORD` إلى كلمة قوية و`SECRET_KEY` إلى قيمة سرية عشوائية ≥32 حرفًا، وحددي `APP_ENV=production` واستخدمي HTTPS و`PUBLIC_BASE_URL=https://...`.
- خادم الإنتاج يحتاج مراقبة وتنبيهات ونسخًا احتياطية لقاعدة SQLite، حماية تسجيل الدخول من محاولات التخمين، حدود استخدام مركزية، سياسة خصوصية، مراجعة المتطلبات الضريبية والامتثال، وحماية أمان إضافية.
- يتعين على الموظف التحقق من **الحساسية الغذائية** وتوافر المكونات قبل قبول الطلب؛ توصيات AI ليست ضمانًا لسلامة الطعام.
- QR الذي يُنشأ محليًا يربط بعنوان محلي ولا يعمل من هواتف أخرى إلا بعد ضبط رابط عام صالح.
- اسم المطعم التجريبي: «بيت المذاق». يمكنك تغييره من الإدارة.
- كل بيانات الطلبات تُحفظ محليًا في `data/commerce.db` الذي ينشأ عند التشغيل لأول مرة. لا تنسخي قاعدة بيانات حقيقية إلى مصادر عامة.

## اختبار البرنامج

من المجلد الرئيسي، ثبّتي pytest إن لم يكن مثبتًا (`pip install pytest`) ثم شغّلي:

```bash
python -m pytest tests -q
```

## بنية الملفات

- `app.py`: الخادم، API، قاعدة بيانات SQLite، حسابات الطلبات وإدارة الجلسة.
- `assistant_engine.py`: محرك التوصيات والمحادثة، وموصل نموذج AI اختياري.
- `voice_gateway.py`: موصل تحويل الصوت إلى نص والعكس.
- `templates/`: صفحات HTML (زبون، إدارة، دخول).
- `static/style.css`: تنسيق المكونات الوظيفية الأساسية.
- `static/brand.css`: تصميم الهوية المتناسقة على مستوى البرنامج كله.
- `static/customer.js`, `static/admin.js`: تفاعل الواجهة والطلبات والصوت.
- `static/images/`: شعار البرنامج وأيقونات التطبيق.
- `start.py`, `run_windows.bat`, `run_mac_linux.sh`: التشغيل المحلي.
- `tests/`: اختبارات الخادم.
- `.env.example`: أمثلة إعدادات البيئة **بدون مفتاح حقيقي**.
